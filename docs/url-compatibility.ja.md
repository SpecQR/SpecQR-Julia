# GS1 URL 互換性の復元

今回の変更は GS1 Digital Link の URL 読み取り・正規化に限ります。通常の
QR 生成、モード選択、符号語、誤り訂正、マスク、描画の実装は変更していません。
実行時依存は引き続き Julia Base と同梱 Base64 のみです。

現在の TypeScript の同一入力を独立実行し、80 件の受理・正規化を復元しました。
空のフラグメント／ベースクエリ、HTTP(S) スラッシュ補完、先頭空白、クエリ中の
バックスラッシュ、資格情報、ASCII ホストのエスケープ、IPv4 別表記、ASCII
reg-name、IPv6 の正規表記が対象です。URL への通信は行いません。

不正なパーセント表記・UTF-8、範囲外のホスト／ポート、GS1 データやその開始位置を
消してしまう生のドットパスは拒否したままです。安全なクエリ中の `.` と `..` は
維持します。Julia は従来から未知クエリの復号 NUL を損失なく保持できるため、
その既存機能とテストは残しています。GDScript 固有の制限を移していません。
Unicode ホストは完全な UTS46 の標準機能がないため未対応で、部分的な IDNA を
新たに実装したかのようには扱いません。

## 既存入力・アサーションの対応

- 既存 1,411 件の入力と歴史的期待値は `gs1-upstream.json` に無変更で保存
- 公開済み Julia の全結果を独立実行して `native-julia-baseline1411.json.gz` に固定
- 80 件の変更後期待値は TypeScript の独立結果 `approved-restorations80.json` を使用
- 診断の優先順のみ変わる 930 / 1038 / 1056 / 1269 は公開 Julia の別入力で証明
- 既存単体テストの `reject_hosts` の全入力を保持し、17 ホストは同じ parse / normalize /
  validate の 3 操作を受理・正規化の正確な肯定アサーションへ移行
- 既存 suffix 入力の空 `#` と `?10=A B` は parse / validate の受理へ移行
- 既存 URI 入力の空ポート、`http:example.com`、先頭空白、パスのバックスラッシュは
  同じ parse 操作で主キー値を正確に検証。その他の拒否アサーションは維持
- 7 旧 authority ホスト×3 操作を保持。6 ホストの18操作は固定 TS 肯定結果、
  `example.0x` の3操作は拒否対照のまま
- 全49共有操作、FNC1 102入力、手動意味論4入力、PNG実デコードを維持

通常 QR の全10,186 golden操作、独立2,400行列、ネイティブ単体テスト、CLI、
新規オフライン利用者、PNGデコーダ、SVG比較を Julia 1.10.12 / 1.13.1 で再実行します。
この変更によって追加OSの動作確認を主張しません。公開・CIは別途、正確なコミットを
対象に確認する必要があります。

## コーパス外の既存制限

ベースパス `/a//b` の空セグメントは従来の前処理により `/a/b` にまとめられます。
ASCII の `xn--` ラベルは通常の reg-name として扱われ、ACE/IDNA の妥当性は
検証しません。従って `xn--a` や `xn--` のような TypeScript が拒否するラベルも
受理され得ます。上記164件とは別の、完全URL互換を主張しない明示的制限です。
有効な punycode まで一律に拒否する変更や不完全なIDNA実装はしていません。
不正なIPv6にUnicodeが含まれる際の文字境界を修正し、内部例外ではなく
公開APIの InvalidGs1Error で拒否するテストを追加しました。
